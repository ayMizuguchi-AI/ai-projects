# レコメンデーションパイプライン設計チャレンジ

## 概要

本試験では、Eコマースの**生データ**（注文・ユーザー・商品・アクセスログ）から**ユーザーごとの商品レコメンデーション**を生成するデータ処理パイプラインを構築していただきます。

レコメンデーション手法は一切自由です。協調フィルタリング・コンテンツベース・ハイブリッド手法など、最適と判断するアプローチを採用してください。パイプライン全体を Docker 環境上で動作させてください。


---

## 進め方

```bash
# 1. リポジトリをクローン
git clone <repository-url>
cd recommendation-challenge

# 2. 仕様を確認
#    docs/spec.md          → 詳細仕様（入出力フォーマット・推薦戦略の例）
#    docs/examples/        → 入出力スキーマのサンプル付き説明

# 3. サンプルデータを確認
#    data/input/            → 入力データ（サンプル）
#    data/expected_output/  → 期待出力のサンプル（全体の10%）

# 4. パイプラインを実装
#    docker-compose.yml を編集し、コードを追加

# 5. ローカルで動作確認
docker compose up

# 6. 提出
./submit.sh
```

---

## 課題

パイプラインは以下の出力を生成する必要があります。

| 出力ファイル | 内容 |
|-------------|------|
| `output/recommendations.json` | ユーザーごとの商品レコメンデーション |

詳細な仕様（推薦戦略・出力フォーマット・評価指標）は [docs/spec.md](docs/spec.md) を参照してください。

---

## 入力データ

`data/input/` ディレクトリに以下のファイルが格納されています。

| ファイル | 形式 | 件数 | 内容 |
|----------|------|------|------|
| `orders.csv` | CSV | 1,000件 | 注文トランザクション |
| `users.json` | JSON | 200件 | ユーザー情報 |
| `products.json` | JSON | 100件 | 商品マスタ |
| `access_logs.jsonl` | JSONL | 5,000件 | アクセスログ |
| `labeled_recommendations_sample.json` | JSON | — | 学習用：ラベル付きレコメンデーションデータ（全体の約30%） |

各ファイルのスキーマ詳細は [docs/examples/input_sample.md](docs/examples/input_sample.md) を参照してください。

> **注意**: 入力データには一部 NULL 値や不正データが含まれています。パイプラインでは適切に処理してください。

---

## 期待出力サンプル

`data/expected_output/` ディレクトリには、**期待出力の10%分**がサンプルとして格納されています。ローカルでの実装検証にご活用ください。

出力フォーマットの詳細は [docs/examples/output_sample.md](docs/examples/output_sample.md) を参照してください。

## 実行要件

| 項目 | 要件 |
|------|------|
| **実行方法** | `docker compose up` で全処理が実行されること |
| **使用言語** | 自由（Python, Go, Rust, Node.js 等） |
| **出力先** | `output/` ディレクトリに出力ファイルを配置 |
| **制限時間** | サンプルデータに対して 10 分以内に完了 |
| **リソース上限** | メモリ 4GB、CPU 2コア |
| **ネットワーク** | 採点時はネットワークが無効化されます。外部 API への依存は避けてください |

---

## 採点方法

提出後、自動で採点が行われます。総合スコアは **600点満点** で、以下の観点から評価されます。

- **正確性** — 非公開テストデータに対するレコメンデーションの精度（F1スコア）
- **パフォーマンス** — 処理速度とリソース効率
- **スケーラビリティ** — データ量増加時の耐性
- **コード品質** — 静的解析による自動評価

各カテゴリの具体的な配点は非公開です。詳細は [docs/scoring_overview.md](docs/scoring_overview.md) を参照してください。

> **重要**: 採点に使用されるテストデータは、提供されるサンプルデータよりも大規模かつ多様です。エッジケース（NULL値、不正フォーマット、重複データ等）への対応も評価に含まれます。

> **アルゴリズムは自由です**: 協調フィルタリング・コンテンツベース・ハイブリッド手法など、最適と判断するアプローチを採用してください。ラベル付き学習データ（約30%）が提供されていますので、教師あり学習にも活用できます。

---

## 提出方法

```bash
# 1. ローカルで動作確認
docker compose up

# 2. 出力ファイルが正しく生成されていることを確認
ls output/

# 3. 提出スクリプトを実行
./submit.sh
```

提出後、自動でビルド・実行の成否が確認されます。採点は管理者側で実行され、結果は別途通知されます。

---

## ルール

- 使用する言語・フレームワーク・ライブラリは自由です
- 全ての処理は Docker コンテナ内で実行してください
- 採点時はネットワーク接続が無効化されます（外部 API への依存は不可）
- `data/input/` ディレクトリの内容を変更しないでください
- 出力ファイルは仕様で定義されたスキーマに正確に従ってください
